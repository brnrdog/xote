Xote comes with a router built on signals. The current URL is a signal, so a route change is an ordinary reactive update: the matching view swaps in and nothing else re-renders.

## Set up the router

Initialize the router once, then render your routes.

```rescript
open Xote

Router.init()

let app = () => {
  <div>
    {Router.routes([
      {pattern: "/", render: _ => <HomePage />},
      {pattern: "/users/:id", render: params =>
        switch params->Dict.get("id") {
        | Some(id) => <UserPage id />
        | None => <NotFoundPage />
        }
      },
    ])}
  </div>
}
```

## Read the current location

`Router.location()` returns the shared location signal. Read it with [`Signal.get`](/docs/api/signal#signal-get) wherever you need the current URL.

```rescript
Effect.run(() => {
  let current = Signal.get(Router.location())
  Console.log2("Current path:", current.pathname)
  None
})
```

The location record has `pathname`, `search` and `hash`.

## Match routes

Patterns can be static or dynamic. A dynamic segment is written `:name`, and its value arrives in the `params` dictionary.

```rescript
{pattern: "/", render: _ => <HomePage />}
{pattern: "/about", render: _ => <AboutPage />}
{pattern: "/users/:id", render: params =>
  switch params->Dict.get("id") {
  | Some(id) => <UserPage id />
  | None => <NotFoundPage />
  }
}
```

## Navigate from code

`Router.push` adds a history entry; `Router.replace` replaces the current one. Both take optional `~search` and `~hash`.

```rescript
Router.push("/users/123", ())
Router.push("/search", ~search="?q=xote", ())
Router.replace("/login", ())
```

## Link between pages

`Router.Link` renders a real `<a href>`, so middle-click, "open in new tab" and crawlers work normally. Only a plain left click is intercepted, and the page doesn't reload.

```rescript
module Nav = {
  @xote.component
  let make = () =>
    <nav>
      <Router.Link to="/" class="nav-link"> {"Home"} </Router.Link>
      <Router.Link to="/docs" class="nav-link"> {"Docs"} </Router.Link>
    </nav>
}
```

## Server rendering

On the server, use `Router.initSSR` instead of `Router.init`. It sets the starting location without touching browser APIs. See [Server rendering](/docs/advanced/ssr) for the full setup.

```rescript
Router.initSSR(
  ~pathname="/docs",
  ~search="?tab=signals",
  (),
)
```

## Example: app with navigation

```rescript
open Xote

Router.init()

module Nav = {
  @xote.component
  let make = () =>
    <nav>
      <Router.Link to="/"> {"Home"} </Router.Link>
      <Router.Link to="/users"> {"Users"} </Router.Link>
    </nav>
}

let app = () => {
  <div>
    <Nav />
    {Router.routes([
      {pattern: "/", render: _ => <HomePage />},
      {pattern: "/users", render: _ => <UsersPage />},
      {pattern: "/users/:id", render: params =>
        switch params->Dict.get("id") {
        | Some(id) => <UserPage id />
        | None => <NotFoundPage />
        }
      },
    ])}
  </div>
}
```

## Tips

- Initialize the router once at the app's entry point, not from leaf components.
- Treat `Router.location()` as shared state. Read it where you need it instead of copying it elsewhere.
- Prefer `Router.Link` for ordinary navigation, so the intent stays obvious in markup.
- Use `Router.initSSR` on the server so routing matches between server rendering and hydration.
- Hosting under a subpath? Pass `~basePath` to `Router.init`; [Deploying](/docs/guides/deploying) covers hosting.
