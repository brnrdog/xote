Server rendering sends real HTML on the first load, so content shows before any JavaScript runs. Hydration then makes that HTML interactive in the browser, without rendering it again.

## How it fits together

Three modules line up with the render flow:

- **SSR** renders nodes to HTML.
- **SSRState** serializes state on the server and restores it in the browser.
- **Hydration** attaches reactivity and event handlers to the existing DOM.

The browser never re-renders what the server already produced. Hydration walks the server HTML, reconnects the reactive parts, and carries on from there.

## Render on the server

Use `SSR.renderToString` for a fragment, and `SSR.renderToStringWithRoot` when you want it wrapped in a root element to hydrate later.

```rescript
open Xote

module App = {
  @xote.component
  let make = () =>
    <div>
      <h1> {"Hello from the server"} </h1>
    </div>
}

let app = () => <App />

let html = SSR.renderToStringWithRoot(app, ~rootId="root")
```

## Render a full document

Use `SSR.renderDocument` when the server sends the whole HTML page. It renders your app into `<div id="root">`, and adds the hydration script and any styles and scripts you list.

```rescript
let html = SSR.renderDocument(
  ~head="<title>Xote App</title>",
  ~styles=["/app.css"],
  ~scripts=["/client.js"],
  ~stateScript=SSRState.generateScript(),
  app,
)
```

## Check where code runs

Use `SSRContext` when code must behave differently on the server and in the browser. `SSRContext.isServer` and `SSRContext.isClient` are plain booleans; `SSRContext.match` picks a branch:

```rescript
let greeting = SSRContext.match(
  ~server=() => "Rendered on the server",
  ~client=() => "Rendered in the browser",
)
```

## Transfer state to the browser

If the server and the browser must start from the same state, declare or register the signals with `SSRState`. On the server they're recorded for the state script; in the browser they're restored from it.

### Create synced state

`SSRState.signal` creates a signal and syncs it in one call:

```rescript
let count = SSRState.signal("count", 0, SSRState.Codec.int)
let name = SSRState.signal("name", "Ada", SSRState.Codec.string)
```

### Sync an existing signal

`SSRState.sync` registers a signal on the server and restores it in the browser:

```rescript
let draft = Signal.make("")
SSRState.sync("draft", draft, SSRState.Codec.string)
```

> **Important:** On the server, `sync` (and `SSRState.signal`) records the signal's value **when you call it**, not when the state script is generated. A signal set after `sync` is sent with its old value. Load the data first, then call `sync`. Likewise, `generateScript` only includes what was registered before it runs, and an argument like `~stateScript=SSRState.generateScript()` runs before `renderDocument` renders.

### Codecs

Codecs turn values into JSON and back. Use the built-in ones for primitives and common containers, or write your own with `SSRState.Codec.make`.

```rescript
SSRState.Codec.int
SSRState.Codec.float
SSRState.Codec.string
SSRState.Codec.bool
SSRState.Codec.array(SSRState.Codec.string)
SSRState.Codec.option(SSRState.Codec.int)
SSRState.Codec.tuple2(SSRState.Codec.int, SSRState.Codec.string)
SSRState.Codec.dict(SSRState.Codec.int)
```

On a long-lived server that renders more than one request, call `SSRState.clear()` before each render so one request's state doesn't leak into the next.

## Hydrate in the browser

Hydration connects the browser runtime to the server-rendered DOM without replacing it.

```rescript
Hydration.hydrateById(app, "root", ~options={
  onHydrated: () => Console.log("hydrated"),
})
```

## Example: shared counter

A typical setup shares one component between the server and the browser.

**Shared component**

```rescript
open Xote

let count = SSRState.signal("count", 0, SSRState.Codec.int)

module App = {
  @xote.component
  let make = () =>
    <div>
      <h1> {"Count: "} {Signal.get(count)} </h1>
      <button onClick={_ => Signal.update(count, n => n + 1)}> {"Increment"} </button>
    </div>
}

let app = () => <App />
```

**Server entry**

```rescript
Router.initSSR(~pathname="/", ())

let html = SSR.renderDocument(
  ~scripts=["/client.js"],
  ~stateScript=SSRState.generateScript(),
  app,
)
```

**Browser entry**

```rescript
Router.init()
Hydration.hydrateById(app, "root")
```

## Hydration markers

During server rendering Xote puts HTML comments around reactive parts. While hydrating, the browser uses those markers to find reactive text, fragments, keyed lists and lazy components.

## Tips

- Render the same component tree on the server and in the browser, so hydration can attach cleanly.
- Initialize the router for each side: `initSSR` on the server, `init` in the browser. See [Routing](/docs/learn/routing).
- Clear `SSRState` between server renders, especially in long-lived processes.
- Pick codecs on purpose: they're the contract between what the server sends and what the browser restores.
- For hosting a server-rendered or pre-rendered site, see [Deploying](/docs/guides/deploying).
