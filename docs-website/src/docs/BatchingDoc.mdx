Batching groups several signal writes so the computeds and effects that depend on them run once, after the batch, instead of after every write.

> **Info:** Updates still happen synchronously. Batching changes how many times dependents run, not whether they run right away.

## Why batch

Without batching, each write can start a new round of downstream work. That's fine for a single update, but noisy when several writes belong together.

```rescript
let firstName = Signal.make("Ada")
let lastName = Signal.make("Lovelace")

let fullName = Computed.make(() =>
  `${Signal.get(firstName)} ${Signal.get(lastName)}`
)

Effect.run(() => {
  Console.log(Signal.get(fullName))
  None
})

Signal.set(firstName, "Grace")
Signal.set(lastName, "Hopper")
```

That effect can run twice, once with "Grace Lovelace" in between. If both writes are one logical update, batch them.

## Batch related writes

Wrap the writes in [`Signal.batch`](/docs/api/signal#signal-batch).

```rescript
Signal.batch(() => {
  Signal.set(firstName, "Grace")
  Signal.set(lastName, "Hopper")
})
```

## What happens inside a batch

Inside a batch, signals update immediately, but dependents only run when the outermost batch finishes. Code inside the batch still reads the latest values.

```rescript
Signal.batch(() => {
  Signal.set(firstName, "Grace")
  Signal.set(lastName, "Hopper")

  Console.log(Signal.peek(firstName)) // "Grace"
  Console.log(Signal.peek(lastName)) // "Hopper"
})
```

## Example: one action, several signals

Batching helps most when one user action updates several related signals.

```rescript
type formState = {
  name: string,
  email: string,
}

let form = Signal.make({name: "", email: ""})
let isSaving = Signal.make(false)
let saveError: Signal.t<option<string>> = Signal.make(None)

let submit = () => {
  Signal.batch(() => {
    Signal.set(isSaving, true)
    Signal.set(saveError, None)
  })
}
```

## Nested batches

Batches can be nested. Dependents run when the outermost batch ends.

```rescript
Signal.batch(() => {
  Signal.set(count, 1)

  Signal.batch(() => {
    Signal.set(count, 2)
    Signal.set(count, 3)
  })
})
```

## Return a value from a batch

A batch returns whatever its callback returns, so you can write and compute a result in one block.

```rescript
let result = Signal.batch(() => {
  Signal.set(count, 10)
  Signal.set(status, "ready")
  "ok"
})
```

## When not to batch

Don't batch by default. If one signal changes and everything else can react naturally, batching adds nothing. Use it when several writes are one logical update.

## Tips

- Batch one logical unit of work, such as a submit, a reset, or a reducer-style update.
- Keep batches short, so the order of writes stays easy to follow.
- Don't use batching to hide duplicated or awkward state. Fix the model first; often a [computed](/docs/learn/computeds) removes the extra writes.
