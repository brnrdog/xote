A signal holds a piece of state. It remembers who reads it and tells them when its value actually changes. Most Xote state starts as a signal.

> **Info:** Xote re-exports [`Signal`](/docs/api/signal#signal-module), [`Computed`](/docs/api/computed#computed-module), and [`Effect`](/docs/api/effect#effect-module) from [rescript-signals](https://brnrdog.github.io/rescript-signals).

## Create a signal

Use [`Signal.make`](/docs/api/signal#signal-make) with a starting value. Optionally pass `~name` for debugging, and `~equals` when the default equality check isn't what you want.

```rescript
open Xote

let count = Signal.make(0)
let userName = Signal.make("Ada", ~name="user-name")
let settings = Signal.make({
  theme: "dark",
  compact: false,
})
```

## Read a signal

There are two ways to read. Pick based on whether the code should run again when the signal changes.

### `Signal.get`: read and subscribe

Use [`Signal.get`](/docs/api/signal#signal-get) inside a computed, an effect, or a component's JSX. That code re-runs whenever the signal changes.

```rescript
let firstName = Signal.make("Ada")
let lastName = Signal.make("Lovelace")

let fullName = Computed.make(() =>
  `${Signal.get(firstName)} ${Signal.get(lastName)}`
)
```

### `Signal.peek`: read without subscribing

Use [`Signal.peek`](/docs/api/signal#signal-peek) when you need the current value but don't want to react to changes. It's handy for logging, snapshots, and one-off reads inside effects.

```rescript
Effect.run(() => {
  let tracked = Signal.get(count)
  let snapshot = Signal.peek(settings)

  Console.log2("Tracked count:", tracked)
  Console.log2("Current theme:", snapshot.theme)
  None
})
```

## Update a signal

### `Signal.set`: replace the value

Use [`Signal.set`](/docs/api/signal#signal-set) when you already know the next value.

```rescript
Signal.set(count, 10)
Signal.set(userName, "Grace")
```

### `Signal.update`: change it based on the current value

Use [`Signal.update`](/docs/api/signal#signal-update) when the next value depends on the current one. The intent stays obvious and you skip an extra read.

```rescript
Signal.update(count, n => n + 1)

Signal.update(settings, current => {...current,
  compact: !current.compact,
})
```

## When a signal notifies

A signal only notifies its dependents when the new value is different from the current one. By default "different" means JavaScript strict equality, `===`.

### Default equality

Setting a primitive to the same value does nothing. For arrays, records and objects, a new reference counts as a change, even if the contents look the same.

```rescript
let count = Signal.make(5)

Signal.set(count, 5) // No update
Signal.set(count, 6) // Notifies dependents

let items = Signal.make([1, 2, 3])
Signal.set(items, [1, 2, 3]) // New array reference, so this updates
```

### Custom equality

To compare compound data by value, pass `~equals` to [`Signal.make`](/docs/api/signal#signal-make).

```rescript
type position = {x: int, y: int}

let position = Signal.make(
  {x: 0, y: 0},
  ~equals=(a, b) => a.x == b.x && a.y == b.y,
)

Signal.set(position, {x: 0, y: 0}) // No update
Signal.set(position, {x: 0, y: 1}) // Update
```

## How dependencies are tracked

Every [`Signal.get`](/docs/api/signal#signal-get) inside a running computed or effect becomes a dependency. Before each re-run the dependencies are cleared and collected again, so they follow your control flow. Below, `temperature` only depends on `fahrenheit` while `useMetric` is `false`.

```rescript
let useMetric = Signal.make(true)
let celsius = Signal.make(20)
let fahrenheit = Signal.make(68)

let temperature = Computed.make(() =>
  if Signal.get(useMetric) {
    Signal.get(celsius)
  } else {
    Signal.get(fahrenheit)
  }
)
```

## Tips

- Keep each signal focused on one job. A small record is fine; a grab bag of unrelated state is not.
- Prefer [`Signal.update`](/docs/api/signal#signal-update) when the next value depends on the current one.
- Treat [`Signal.peek`](/docs/api/signal#signal-peek) as a snapshot tool, not your default way to read.
- Add custom equality only when strict equality causes real noise in the UI or in effects.
- If a value can be worked out from other signals, don't store it in its own signal: derive it with a [computed](/docs/learn/computeds). To connect signals to timers, requests or browser APIs, use an [effect](/docs/learn/effects).
