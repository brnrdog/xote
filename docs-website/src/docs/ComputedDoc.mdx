A computed is a value worked out from other signals. You describe how to derive it once, and Xote keeps it in sync, so you never update two signals by hand.

> **Important:** [`Computed.make`](/docs/api/computed#computed-make) returns a [`Signal.t<'a>`](/docs/api/signal#signal-type). You read it with [`Signal.get`](/docs/api/signal#signal-get) or [`Signal.peek`](/docs/api/signal#signal-peek), like any other signal. It has no `set`: only its function writes it.

## Create a computed

Pass [`Computed.make`](/docs/api/computed#computed-make) a function. Every signal the function reads becomes an input.

```rescript
open Xote

let price = Signal.make(100)
let quantity = Signal.make(3)

let subtotal = Computed.make(() =>
  Signal.get(price) * Signal.get(quantity)
)
```

[`Computed.make`](/docs/api/computed#computed-make) also accepts `~equals`. By default a computed doesn't compare: when it recalculates, everything that reads it runs again, even if the new value is the same. Pass `~equals` (for example `~equals=(a, b) => a == b`) and an equal result leaves its dependents alone.

## Read a computed

Read a computed exactly like a signal: [`Signal.get`](/docs/api/signal#signal-get) to subscribe, [`Signal.peek`](/docs/api/signal#signal-peek) for a one-off read. A computed can depend on another computed.

```rescript
let subtotal = Computed.make(() =>
  Signal.get(price) * Signal.get(quantity)
)

let total = Computed.make(() =>
  Signal.get(subtotal) + 50
)

Console.log(Signal.get(total))
```

## Recomputing only when read

When an input changes, a computed is marked dirty right away, but it only recomputes when someone reads it. Derived values nobody uses cost almost nothing.

```rescript
let count = Signal.make(0)

let doubled = Computed.make(() => {
  Console.log("recomputing")
  Signal.get(count) * 2
})

Signal.set(count, 1)
// Nothing logged yet

ignore(Signal.get(doubled))
// Logs "recomputing"
```

## Conditional dependencies

A computed collects its inputs again every time it runs, so conditionals are fine: whichever branch runs decides which signals it depends on.

```rescript
let useMetric = Signal.make(true)
let celsius = Signal.make(20)
let fahrenheit = Signal.make(68)

let temperature = Computed.make(() =>
  if Signal.get(useMetric) {
    Signal.get(celsius)
  } else {
    Signal.get(fahrenheit)
  }
)
```

## Cleaning up

Most computeds need no cleanup. They dispose themselves when nothing subscribes to them anymore, and one created inside a component or effect goes away with it.

If you create a long-lived computed outside any component and want to tear it down yourself, call [`Computed.dispose`](/docs/api/computed#computed-dispose).

```rescript
let doubled = Computed.make(() => Signal.get(count) * 2)

// Use it for a while...

Computed.dispose(doubled)
```

## Derive, don't copy

If a value can be derived from other signals, use a computed instead of copying it into another signal.

```rescript
// Avoid this
let count = Signal.make(0)
let doubled = Signal.make(0)

let increment = () => {
  Signal.update(count, n => n + 1)
  Signal.set(doubled, Signal.get(count) * 2)
}

// Prefer this
let count = Signal.make(0)
let doubled = Computed.make(() => Signal.get(count) * 2)
```

## Tips

- Keep computeds pure. If the code talks to the outside world, it belongs in an [effect](/docs/learn/effects).
- Read computeds with [`Signal.get`](/docs/api/signal#signal-get) or [`Signal.peek`](/docs/api/signal#signal-peek); they are signals at the type level.
- Don't copy derived values into writable signals unless you really need editable local state.
- Pass `~equals` when a computed often recalculates to the same value and the things that read it are costly to run again.
- To show derived values in the UI, read them in a component's JSX; see [Rendering](/docs/learn/rendering).
