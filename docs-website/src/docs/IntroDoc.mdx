Xote is a small UI library for [ReScript](https://rescript-lang.org/). You keep state in signals, write components in JSX, and when a value changes Xote updates exactly the text or attribute that shows it. Nothing else re-renders.

## A first look

A signal holds a value. A computed derives one. The component reads both, and each read becomes a tiny live binding in the page.

<DocsExamplePanel
      filename="Counter.res"
      code={`let count = Signal.make(0)
let doubled = Computed.make(() => Signal.get(count) * 2)

@xote.component
let make = () =>
  <div>
    <button onClick={_ => Signal.update(count, n => n + 1)}>
      {"Clicked "}
      {Signal.get(count)}
      {" times"}
    </button>
    <p> {"Doubled: "} {Signal.get(doubled)} </p>
  </div>`}
    >
      <IntroCounterDemo />
    </DocsExamplePanel>

Click the button and only the two numbers change. The component function ran once, when it was first rendered; the button, the paragraph and the static text were built then and stay put.

## Why Xote

- **Updates where they matter.** No virtual DOM and no re-running components. A change goes straight from the signal to the DOM node that reads it.
- **A small surface.** Signals, computeds and effects for state; JSX and a handful of `View` helpers for UI. Most apps need little else.
- **Types all the way down.** ReScript checks your state, props and events at compile time, and compiles fast.
- **The rest is built in.** A router, server rendering with hydration, context and async resources come in the same package.

## What's in the box

| Module | What it's for |
| --- | --- |
| [`Signal`](/docs/learn/signals) | State you can read and update |
| [`Computed`](/docs/learn/computeds) | Values derived from other signals |
| [`Effect`](/docs/learn/effects) | Side effects that rerun when their inputs change |
| [`View`](/docs/learn/components) and JSX | Components, lists, conditions, refs, portals |
| [`Context`](/docs/learn/context) | Values shared with everything a component renders |
| [`Resource`](/docs/learn/async-data) | Async data as signals, with Suspense |
| [`Router`](/docs/learn/routing) | URL matching, links and navigation |
| [`SSR` and `Hydration`](/docs/advanced/ssr) | Render on the server, pick up on the client |

## Where to start

- **New to Xote?** Go to [Quick start](/docs/quick-start) to set up a project, then read [Thinking in signals](/docs/thinking-in-signals) for the one idea everything else builds on.
- **Like learning by building?** Follow the [tutorial](/docs/tutorial) to make a small temperature converter.
- **New to ReScript?** [Learning ReScript](/docs/learning-rescript) covers the syntax you'll see in these docs.
- **Coming from React or SolidJS?** See how Xote [compares to React](/docs/comparisons/react) and [to SolidJS](/docs/comparisons/solidjs).
- **Not using ReScript?** Xote's runtime also works [from JavaScript](/docs/javascript).

Xote's reactive core comes from [rescript-signals](https://brnrdog.github.io/rescript-signals), which follows the same model as the JavaScript signals proposal.
