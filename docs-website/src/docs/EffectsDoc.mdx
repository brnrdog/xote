An effect connects signals to the outside world. It runs right away, remembers the signals it read, and runs again when any of them change.

Use effects for browser APIs, timers, network work, logging, or anything else that should happen because state changed. Don't use them to compute values: that's what [computeds](/docs/learn/computeds) are for.

## Create an effect

Use [`Effect.run`](/docs/api/effect#effect-run). The function returns `None`, or `Some(cleanup)` as shown below. If you need to stop the effect yourself, use [`Effect.runWithDisposer`](/docs/api/effect#effect-runwithdisposer).

```rescript
open Xote

let count = Signal.make(0)

Effect.run(() => {
  Console.log2("Count:", Signal.get(count))
  None
})
```

## What an effect reacts to

Every [`Signal.get`](/docs/api/signal#signal-get) inside the effect subscribes it to that signal. Dependencies are collected again on every run, so below, `name` and `age` only matter while `showDetails` is `true`.

```rescript
let showDetails = Signal.make(false)
let name = Signal.make("Ada")
let age = Signal.make(36)

Effect.run(() => {
  if Signal.get(showDetails) {
    Console.log2("Name:", Signal.get(name))
    Console.log2("Age:", Signal.get(age))
  }
  None
})
```

## Clean up after yourself

Return `Some(cleanup)` to undo what the effect set up. Cleanup runs before the next run and when the effect is disposed. Here, changing `intervalMs` clears the old interval before starting a new one.

```rescript
@val external setInterval: (unit => unit, int) => int = "setInterval"
@val external clearInterval: int => unit = "clearInterval"

let intervalMs = Signal.make(1000)

Effect.run(() => {
  let id = setInterval(() => Console.log("tick"), Signal.get(intervalMs))
  Some(() => clearInterval(id))
})
```

## Stop an effect

An effect created inside a component stops when the component goes away. To stop one yourself, use [`Effect.runWithDisposer`](/docs/api/effect#effect-runwithdisposer). It returns a record with a `dispose` function, which runs any pending cleanup and unsubscribes the effect.

```rescript
let disposer = Effect.runWithDisposer(() => {
  Console.log(Signal.get(count))
  None
})

disposer.dispose()
```

## Read without subscribing

To use a value inside an effect without re-running when it changes, use [`Signal.peek`](/docs/api/signal#signal-peek) for one read, or [`Signal.untrack`](/docs/api/signal#signal-untrack) for a whole block.

```rescript
let debug = Signal.make(true)

Effect.run(() => {
  let tracked = Signal.get(count)

  if Signal.peek(debug) {
    Console.log2("Debug count:", tracked)
  }

  None
})
```

## What effects are for

- **Browser APIs:** document title, localStorage, media queries, history and scroll state
- **Timers and subscriptions:** intervals, event listeners, sockets and observers
- **Synchronization:** pushing state into another system
- **Diagnostics:** logging, instrumentation and dev-only inspection

## Effect or computed?

Ask one question: is the result another value, or is it work outside the signal graph?

- **A value derived from other values:** use a [computed](/docs/learn/computeds).
- **Talking to something external:** use an effect.

## Tips

- Keep each effect focused on one kind of external work, so its cleanup stays obvious.
- Return cleanup whenever you allocate timers, listeners, requests or subscriptions.
- Don't use effects to keep derived state in sync. If the output is another value, use a computed.
- Use [`Signal.peek`](/docs/api/signal#signal-peek) and [`Signal.untrack`](/docs/api/signal#signal-untrack) on purpose: they opt out of tracking.
- When several writes should trigger one run instead of many, wrap them in a [batch](/docs/advanced/batching). For effects tied to a component's DOM, see [Refs and lifecycle](/docs/learn/lifecycle).
